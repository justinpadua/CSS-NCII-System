## 4. Approved Business Rules

- **Student login:** Students register with Full Name, Program, and password; the system generates a unique Account ID. Admin approval is required. Only ACTIVE accounts can log in with Account ID + Password. Passwords are BCrypt-hashed.
- **Admin login:** Username + Password; email is not required. Password verification uses BCrypt; Admin sessions are cookie-based and stored through Spring Security's HTTP session context.
- **Learning flow:** Each Discussion has seven ordered stages with canonical codes: `PRE_TEST`, `DEFINITIONS`, `EXPLANATION`, `EXAMPLES`, `VIDEO_LESSONS`, `ACTIVITY`, `POST_TEST`.
- **Progression:** Discussions proceed in order; required assessment submissions complete their stages. Completed work and scores remain preserved. COC 2 unlocks only after passing the COC 1 Generalized Post-test.
- **Question types:** Only `MULTIPLE_CHOICE`, `TRUE_FALSE`, and `MULTIPLE_SELECT`.
- **Answer JSON:** Multiple choice uses `{"choiceId": 12}`; true/false uses `{"value": true}` with a JSON boolean; multiple select uses `{"choiceIds": [12, 14]}`. Choice IDs must belong to the question; duplicate multiple-select IDs and malformed/incorrectly shaped responses are rejected. Multiple-select order does not matter.
- **Scoring:** Exact match, no partial credit; correct answers receive full points and incorrect answers receive zero. Generalized Post-tests pass at 70%; compare the unrounded score ratio for threshold decisions.
- **Discussion assessments:** A student submits each Discussion assessment once. Interrupted attempts can be resumed. Submitted answers, scores, and history are retained. Pre-test feedback shows score and incorrect questions; correct answers may be shown. Activity and Discussion Post-test feedback include correct answers.
- **Generalized Post-tests:** Each competency has three initial submitted attempts. Interrupted attempts resume and do not consume allowance; only submitted attempts count. Each Admin authorization grants exactly three additional attempts and stores the authorizing Admin and authorization time. Previously passed competencies remain passed.
