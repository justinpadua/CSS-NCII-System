### Proposed complete Activity task

**Activity title: Safe Shop, Smart Service — Tool Use and Cleaning Sequence**

**Objective:** Identify appropriate servicing tools and arrange a safe sequence for cleaning dust from a desktop PC.

**Materials:** Worksheet and pen. Optional instructor demonstration: an unplugged desktop system unit, anti-static brush, wrist strap, tweezers, digital multimeter, and PSU tester. No learner should open a PSU enclosure or probe live equipment.

**Part A — Match the tool.** Match each description to one item in the word bank. Use each answer once.

Word bank: Anti-static brush · Antistatic wrist strap · Digital multimeter · Hammer · Power supply tester · Tweezers

1. Measures electrical quantities such as voltage, resistance, or current when the user selects the correct mode and follows safe procedures.
2. Helps check basic PSU output conditions using its intended connectors and instructions.
3. Worn and connected to an approved ESD-safe ground to reduce electrostatic charge on the technician.
4. Helps handle very small screws or jumpers.
5. Used to remove loose dust from suitable internal surfaces while reducing static risk when used correctly.

**Part B — Put the cleaning steps in order.** Number these steps 1–5. Do not perform a live repair. Keep the computer disconnected from power before opening it. Use only the instructor-approved cleaning method; do not use liquids or open the PSU.

- Clean loose dust using an anti-static brush and suitable safe technique; avoid forcing or damaging components.
- Shut down the computer using its operating system.
- Open the case panel after power has been disconnected and the work area is ready.
- Disconnect the power cable and other external cables.
- Put on a properly grounded antistatic wrist strap before handling internal components.

**Existing Parts C and D:** Retain the current shop-readiness selection and costing/safety questions in the source Activity; they are not part of the identified prompt gap.

**Steps:** Complete the matching and sequencing independently. If using the optional demonstration equipment, first obtain instructor approval, identify the test unit, isolate power, and demonstrate the order without opening the PSU. Record any safety issue you notice.

**Expected output:** Completed five-item matching and ordered sequence, plus the existing Parts C and D responses.

- Suggested rubric (18 points): Part A 5 (one each); Part B 5 (one each); existing Part C 4 (one for each correct shop item, subtract one for each selected distractor, minimum zero); existing Part D 4 (2 for correct ₱750 computation, 1 for a relevant safety rule, 1 for a valid reason). **Part B — Match the part to its connection.** Choose from: CPU cooler fan · Front audio jack · Graphics card · Main power from the PSU · Memory module · NVMe SSD.

**Part C — Diagnose it.** Select the first check from the existing word bank for each scenario: Audio settings and driver · Monitor cable and RAM seating · Power cable, outlet, and PSU switch · Replace the case · Temperatures, power, and memory.

**Existing Parts D and E:** Retain the current assembly-precaution choices and first-three-troubleshooting-steps response.

**Steps:** Do the paper sequencing/matching first. If no equipment is available, submit the worksheet only; no physical equipment is required. For an optional practical demonstration, use only an instructor-approved, unplugged unit; verify power is disconnected, use the lab's ESD procedure, handle parts by their edges, use no force, and never open the PSU. Point out connectors without removing parts unless specifically authorized. For each symptom, state why your check is first and identify one later check only if the first check passes.

**Expected output:** Ordered sequence; six matches; four first-check selections with one-sentence reasons; existing D/E responses.

## 4. COC 1 — Discussion 4: Creation of Portable Bootable Devices

**Original source:** `learning-content/COC-1/Lesson-04/06-Activity.md`

### Relevant lesson concepts

Legitimate ISO sources; bootable USB versus ISO file; matching GPT/UEFI or MBR/legacy requirements; USB erasure warning; DiskPart commands and destructive disk risks; `oscdimg` creates ISO images but does not automatically make an arbitrary image bootable.

### Proposed complete Activity task

**Activity title: Boot It Up — Plan and Verify Installation Media**

**Objective:** Arrange safe bootable-media preparation and distinguish disk-management commands from ISO creation.

**Materials:** Worksheet and pen. Optional instructor demonstration on a disposable USB with no needed data and an authorized lab computer. A written simulation is acceptable; students must not run DiskPart or erase a device without direct authorization.

**Part A — Order the Rufus procedure.** Number these seven steps in a safe sequence:

- Click START only after checking the selected drive and settings; acknowledge the erase warning only after confirming the USB is the intended disposable device.
- Obtain a valid operating-system ISO from its official source.
- Wait for Rufus to report completion, safely eject the USB, and test it from the target computer's boot menu when authorized.
- Choose the partition scheme appropriate to the target's firmware and OS instructions.
- Insert the USB after backing up its contents.
- Open Rufus and select the correct USB device.
- Select the ISO image in Rufus and review the options.

**Part B — Match the command/tool to its purpose.** Use: `assign` · `diskpart` · `list disk` · `list volume` · `oscdimg` · `select disk`.

1. Starts the Windows disk-management command environment.
2. Displays connected disks so their numbers/capacities can be checked.
3. Chooses a disk for subsequent commands; selecting the wrong disk is dangerous.
4. Displays volumes and their drive letters/labels.
5. Assigns a drive letter to a selected volume.
6. A Windows ADK utility that can build an ISO from a prepared folder tree; bootability still depends on correct boot files/options.

**Part C — True or False.** Mark each statement T or F; correct any false statement in one sentence.

1. An ISO file is already a bootable USB as soon as it is downloaded.
2. Writing installation media can erase the selected USB drive.
3. A generic data ISO made from a folder is necessarily bootable.
4. DiskPart manages disks, partitions, and volumes; it is not an ISO-authoring tool.
5. Before a disk command or media write, verify the target device and authorization.

**Existing Part D:** Retain the three-item customer checklist.

**Expected output:** Ordered procedure, six command matches, five T/F answers with corrections, and existing customer checklist.

### Instructor-only expected answer and evaluation reference

- Part A: official ISO; insert/backup USB; open Rufus/select device; select ISO; choose appropriate scheme; verify and start/confirm erase; safely eject/test. Existing companion key states a similar order; instructor should verify this seven-item wording and its exact ordering.
- Part B: `diskpart`; `list disk`; `select disk`; `list volume`; `assign`; `oscdimg`.
- Part C: 1 False; 2 True; 3 False; 4 True; 5 True.
- Suggested rubric (23 points): Part A 7 (one per step in an acceptable safe order); Part B 6; Part C 7 (one for each T/F item and one each for the two false-statement corrections); existing Part D 3 (one per reasonable customer check/disclosure). Require the learner to identify that media creation erases the chosen USB and to verify the target before starting. For the optional demo, use only an approved disposable USB; never run destructive DiskPart commands as part of this activity. A paper simulation is the default and is complete without hardware.

**Assumptions / approval needed:** The wording is drafted from the explanation and existing key. Instructor must decide whether learners perform a supervised Rufus demonstration or complete a no-write simulation. No student should execute destructive disk commands for this worksheet.

## 6. COC 1 — Discussion 6: Computer Testing and Documentation

**Original source:** `learning-content/COC-1/Lesson-06/06-Activity.md`  
**Missing parts:** Part A seven test steps; Part B term descriptions; Part C four response scenarios.

### Relevant lesson concepts

Inspect before testing; record configuration and idle baseline; choose a component-specific workload; monitor continuously; stop on unsafe readings/errors/instability; interpret results only against component guidance; isolate faults and document/retest. The lesson warns that no universal temperature or duration is a pass/fail rule.

### Proposed complete Activity task

**Activity title: Push It, Measure It — Supervised Test and Record**

**Objective:** Plan a controlled component test, recognize observations requiring action, and document results without claiming more than the test establishes.

**Materials:** Worksheet and pen. Preferred low-risk option: instructor-provided sample log/results. Optional hands-on option: instructor-approved lab PC, monitoring utility, and component-specific test utility under continuous supervision. Save work first. Do not run a stress test on a personal/customer computer or adjust voltage/overclocking settings.

**Part A — Order the test.** Number the seven stages:

- Check assembly, cooling, fans, and connections before testing.
- Start one appropriate component test while monitoring.
- Prepare a report with results and recommendations.
- Record observed peak temperatures and errors in the test log.
- Stop the workload when complete or immediately if a safety limit/problem occurs.
- Record hardware/software specifications and idle baseline readings.
- Monitor temperatures, errors, fan behavior, and stability continuously.

**Part B — Match the term.** Use: Artifacts · Fault isolation · Idle temperature · Peak temperature · Test log · Thermal throttling.

1. Performance reduction used to manage temperature or power conditions.
2. Unexpected visual corruption or defects during graphics output.
3. Temperature observed before the selected workload begins.
4. Highest temperature observed during the defined test interval.
5. Testing one likely cause/component at a time to narrow a fault.
6. Record of settings, duration, observations, results, and actions.

**Part C — Choose the safest response.** Word bank: Ignore the result · Report no issue observed under the tested conditions · Reseat or replace the RAM, then retest · Stop the test · Suspect a graphics problem.

1. The test reaches the hardware manufacturer's limit, or cooling fails.
2. A GPU workload produces visible artifacts.
3. A memory diagnostic reports errors; after recording the exact test/settings, an authorized technician is ready to check seating or isolate modules.
4. A test completes its selected duration with no reported errors; describe the result without claiming that the system is permanently fault-free.

**Existing Part D:** Use the source's sample data (idle 40°C, peak 98°C, performance drop after five minutes, no crash) only as a paper interpretation case. State that the observed performance drop and peak reading warrant investigation; compare with the exact CPU model/manufacturer and system guidance. Do not infer a universal failure limit from 98°C alone or recommend a component repair without diagnosis.

**Expected output:** Ordered seven-stage plan, six term matches, four responses and a short evidence-based conclusion/recommendation for D.

### Instructor-only expected answer and evaluation reference

- Part A: inspect/cooling (1); record specs/baseline (2); start selected test (3); monitor (4); stop safely (5); record peak/errors (6); report/recommendations (7). Accept logging during monitoring if the learner explains that monitoring and recording overlap in a real test.
- Part B: Thermal throttling; Artifacts; Idle temperature; Peak temperature; Fault isolation; Test log.
- Part C: Stop the test; Suspect a graphics problem; Reseat or replace RAM only after authorized safe checks; Report no issue observed under the tested conditions. This result is limited to the selected workload, duration, configuration, and observed data. It does not predict future performance or guarantee absence of intermittent faults.
- Part D: Suggested response: the observed performance drop plus high recorded peak may indicate thermal throttling; stop/avoid repeated load and inspect cooling/fan/airflow under authorization; compare sensor values to exact manufacturer's limits and retest only after safe correction. No universal numeric threshold.
- Suggested rubric (23 points): Part A 7 (one per step in acceptable sequence); Part B 6; Part C 4 (one per scenario); Part D 6 (2 for accurately citing given evidence, 2 for a qualified interpretation that avoids a universal temperature claim, 2 for a safe, relevant next step). Any claim that a short test guarantees permanent stability earns no conclusion credit. Require a clear stop condition and no repeated unsafe load.

**Assumptions / approval needed:** Use simulated data if safe supervised equipment is unavailable; physical stress testing is optional and must be supervised continuously. The proposed wording replaces the original answer-bank wording “Report the system as stable” with a bounded observation. Instructor approval is needed before making that change to the source Activity. Model-specific temperature guidance must be selected by the instructor.
